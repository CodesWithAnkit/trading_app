### 2. Error Handling & HTTP Status Codes (Good)
**Observation**: The controllers appropriately catch database errors and throw NestJS `HttpException` with `HttpStatus.INTERNAL_SERVER_ERROR`. 
**Recommendation**: Continue this pattern. If we eventually want to distinguish between specific database constraints (e.g., unique key violations on insert), we can map those Supabase error codes to more specific HTTP codes like `409 CONFLICT` or `400 BAD REQUEST`.

**Observation**: The `getSignals` and `getTrades` endpoints currently run `select('*')` without `.limit()` or pagination.
**Recommendation**: As the live database accumulates signals over time, you will want to add `.limit(100)` and potentially offset/cursor-based pagination to these GET endpoints to avoid massive payloads.

### 4. Security & Environment Keys (Good)
**Observation**: The backend relies on standard environment variables without committing them to source control, and we discovered/handled network routing (IPv6) constraints for local connections gracefully by falling back to the REST API / Dashboard execution.
**Recommendation**: Make sure `SUPABASE_SECRET_KEY` (service role key) is never leaked into the `apps/web/.env` or any client-side bundles.
